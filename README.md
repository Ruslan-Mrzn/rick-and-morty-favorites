# R & M Favorites — микрофронт

Виджет «Избранные персонажи», вынесенный в отдельное приложение и подключаемый к хосту через Module Federation. Хост загружает `remoteEntry.js` и рендерит виджет, передавая данные и тексты через props.

## Стек

- React 19
- TypeScript
- Vite
- Module Federation (`@originjs/vite-plugin-federation`)
- SCSS Modules
- ESLint + Stylelint + Prettier + Husky + lint-staged

## Установка

```bash
npm install
```

## Скрипты

```bash
npm run dev     # запуск dev-сервера (порт 5173)
npm run build   # сборка продакшн-версии
npm run preview # предпросмотр сборки
npm run lint    # ESLint
npm run lint:css        # Stylelint
npm run prettier:fix    # форматирование всех файлов
```

## Функционал

- **Избранные персонажи** — панель со списком, открывается по клику на иконку
- **Удаление из избранного** — кнопка `×` у каждого элемента
- **Счётчик** — показывает количество избранного (показывает `9+` при превышении порога)
- **Тёмная тема** — переключение через CSS-переменные (атрибут `data-theme="dark"`)
- **Стенд** — в dev-режиме поднимается standalone-страница с моковыми данными, чтобы отлаживать виджет без хоста

## Особенности

- **Module Federation (remote):** `FavoriteCharacters` экспортируется как `./FavoriteCharacters` и загружается хостом динамически
- **Динамический `base`** путь для деплоя на Vercel и GitHub Pages — задаётся через `VITE_BASE_PATH` при сборке. На Pages подставляется в CI, на Vercel используется `/` по умолчанию
- **Стенд:** в dev-режиме `main.tsx` подключает `standalone.scss` и рендерит `App` с моковыми данными. В продакшн-сборке `index.html` из `dist` удаляется
- **Husky + lint-staged:** на коммит прогоняются `eslint --fix`, `prettier --write`, `stylelint --fix`

## Docker

Для разработки через Docker — образ собирается один раз с Node.js 22, а процессы запускаются в терминале.

**Команды:**

```bash
make docker-build-dev   # собрать образ (node:22-alpine + зависимости)
make docker-up-dev      # запустить контейнер (порты 5173 и 5001)
make docker-down        # остановить контейнер
make docker-check       # линтеры в контейнере
```

**Режимы работы (внутри контейнера):**

| Команда         | Порт | Назначение                                                        |
| --------------- | ---- | ----------------------------------------------------------------- |
| `npm run dev`   | 5173 | Standalone-стенд с моками (HMR) — разработка виджета без хоста    |
| `npm run serve` | 5001 | Режим микрофронта — `remoteEntry.js` доступен для загрузки хостом |

Переключение между режимами через Ctrl+C. Порт 5001 пробрасывается на хост.

## GitHub Codespaces

Проект полностью готов к работе в GitHub Codespaces через Dev Containers.

**Подготовка (один раз):**

1. Сделать **Fork** этого репозитория на свой GitHub
2. То же самое сделать с хост-репозиторием `rick-and-morty` (если планируешь связку микрофронта)

**Быстрый старт (в форке):**

1. Открыть **Code → Codespaces → Create a new codespace**
2. Контейнер поднимется автоматически (порты 5173 и 5001)
3. **Dev-стенд:** в терминале `npm run dev`, открыть порт 5173 из вкладки Ports
4. **Режим микрофронта:** Ctrl+C → `npm run serve`, скопировать публичный URL порта 5001
5. В форке хост-репозитория (`rick-and-morty`) в `vite.config.ts` прописать в `const remoteUrl` адрес публичного 5001 порта микрофронта:
   ```
   <адрес публичного 5001 порта микрофронта>/assets/remoteEntry.js
   ```
   и перезапустить `npm run dev` хоста

> ⚠️ **Не забудь:** в Codespaces порт 5001 по умолчанию приватный. Перед запуском хоста нажми ПКМ на порту 5001 во вкладке Ports → **Port Visibility** → **Public**, иначе хост не сможет загрузить `remoteEntry.js`.
